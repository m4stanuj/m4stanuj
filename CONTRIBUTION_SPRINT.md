# M4ST Contribution Sprint

This is a rolling contribution plan for making the public M4ST GitHub surface stronger through real, useful commits.

## Rules

- No fake backdated history.
- No empty commits.
- No deleting or hiding useful work.
- Every contribution should improve proof, setup, trust, safety, examples, tests, or demos.

## 14-Day Upgrade Loop

### Day 1: Profile + MAST Trust Layer

- Refresh profile README links and current focus.
- Add MAST `SECURITY.md`.
- Add MAST `CONTRIBUTING.md`.
- Add MAST `.env.example`.
- Add MAST `docs/SAFETY.md`.

### Day 2: CAI-OSINT Safety Polish

- Reframe top README copy around authorized defensive use.
- Add stronger scope and written-permission language.
- Add `SECURITY.md` if missing.

### Day 3: Semantic Cache Proof Notes

- Add `BENCHMARKS.md`.
- Explain benchmark environment and limitations.
- Soften broad savings claims into observed/tested claims.

### Day 4: OpenWork Setup Docs

- Add `docs/MCP_SETUP.md`.
- Add common IDE setup examples.
- Add troubleshooting notes.

### Day 5: LeadSniper Examples

- Add safe sample lead data.
- Add review-first export walkthrough.
- Make human approval points explicit.

### Day 6: MAST Demo Polish

- Expand `DEMO_STORYBOARD.md`.
- Add terminal demo commands.
- Add verification checklist.

### Day 7: mast-llm-router Reliability Docs

- Add routing examples.
- Add failure-mode notes.
- Add cache/fallback explanation.

### Day 8: Repo Metadata Pass

- Align repo descriptions.
- Add topics where missing.
- Make portfolio links consistent.

### Day 9: CI Tightening

- Add lightweight syntax checks where missing.
- Add secret-scan patterns for provider keys.
- Avoid heavyweight jobs that make contribution friction painful.

### Day 10: Screenshots and Demos

- Add static screenshots or terminal captures.
- Keep assets small and useful.
- Link demos from README cards.

### Day 11: Changelog Pass

- Add or update `CHANGELOG.md` entries.
- Keep release notes short and readable.

### Day 12: Docs Consistency

- Standardize headings: What it is, Why it exists, Setup, Safety, Examples, Roadmap.
- Link related M4ST repos.

### Day 13: Tests

- Add minimal tests for config loading, routing, parsing, or safety checks.
- Prefer small tests that can run quickly in CI.

### Day 14: Portfolio Sync

- Update `m4st.vercel.app` project data with any newly polished repos.
- Keep public site and GitHub story aligned.

## Weekly Rhythm

- Monday: docs
- Tuesday: tests
- Wednesday: examples
- Thursday: CI
- Friday: demos
- Saturday: changelog/release polish
- Sunday: portfolio/profile sync
